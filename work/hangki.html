01

문제 정의

학생들은 점심 메뉴를 확인하려고 학식 앱을 열지만, 로그인 → 식당 선택 → 날짜 선택을 거쳐야 오늘 메뉴가 나왔어요. 그래서 대부분 앱을 포기하고 식당 앞 게시판까지 가서 메뉴를 확인했어요.

“메뉴 하나 보려고 세 번 눌러야 하니까, 그냥 식당 앞에 가서 봐요.”

— 인터뷰 참여자 P3 (2학년)

점심시간은 50분뿐이라 메뉴 확인이 늦어지면 줄이 길어져요. 식당 입장에서도 앱으로 품절이나 메뉴 변경을 알려도 학생들이 보지 않아 안내가 전달되지 않았어요.

문제 정의 문장

점심을 고르는 학생이 수업 사이 짧은 시간에 메뉴를 확인할 때, 여러 단계를 거쳐야 해서 앱을 포기한다. 어떻게 하면 앱을 열자마자 오늘 먹을 메뉴를 고를 수 있게 만들 수 있을까?

02

리서치

학생들이 실제로 언제, 어떤 정보를 보고 메뉴를 고르는지 알기 위해 인터뷰로 행동을 듣고, 설문으로 규모를 확인하고, 다른 학교 앱과 배달 앱의 메뉴 화면을 비교했어요.

  • 사용자 인터뷰

    8명 · 2주

  • 설문

    126명 응답

  • 경쟁 서비스 분석

    6개 서비스

[리서치 과정 사진 · 어피니티 다이어그램]

주요 발견

  • 메뉴는 주로 수업 사이 10분 쉬는 시간에 확인해요 — 설문 응답자의 71%가 이 시간대를 꼽았어요.
  • 로그인 화면에서 가장 많이 떠나요 — 인터뷰 8명 중 6명이 '로그인이 풀려 있어서' 앱을 닫은 경험이 있었어요.
  • 메뉴 이름보다 가격과 품절 여부를 먼저 봐요 — 인터뷰에서 가장 많이 나온 질문은 '아직 있어요?'였어요.

03

인사이트

발견한 내용을 '언제 · 무엇을 · 어떻게' 기준으로 묶어 세 가지 디자인 기회로 정리했어요.

  • 01

    열자마자 오늘 메뉴

    로그인과 식당 선택 없이, 앱 첫 화면이 곧 오늘의 메뉴가 되어야 해요.

  • 02

    10분 안에 결정

    쉬는 시간 안에 고를 수 있도록 가격, 위치, 대기 정도를 한눈에 비교하게 해요.

  • 03

    '아직 있어요?'에 답하기

    품절과 메뉴 변경을 바로 알려 헛걸음을 줄여요.

04

설계

메뉴 확인까지 5단계였던 흐름을 홈 한 화면으로 줄이는 정보 구조를 만들고, 홈 화면 구성을 두 가지 안으로 나눠 테스트했어요.

[정보 구조도 · 사용자 흐름]

Decision

직접 눌러서 두 안을 비교해 보세요

선택: B안 — 이유: 테스트 참여자 5명 모두 B안에서 더 빨리 메뉴를 골랐고, 식당보다 메뉴를 먼저 본다는 리서치 결과와도 맞았어요.

05

최종 디자인

홈 하나에 오늘의 메뉴, 품절 알림, 식당별 대기 정도를 모았어요. 자주 먹는 메뉴는 즐겨찾기로 저장해 나오는 날 알림을 받을 수 있어요.

← 옆으로 넘겨 보세요 →

AFTER개선 · 홈 한 화면에서 오늘 메뉴 확인
BEFORE기존 · 로그인 → 식당 → 날짜 → 메뉴

드래그해서 개선 전후를 비교해 보세요 — 5단계였던 메뉴 확인이 홈 한 화면으로 바뀌었어요.

06

결과 · 회고

학생 5명과 개선 전후 프로토타입으로 사용성 테스트를 진행했어요. 실제 서비스로 출시하지는 않았고, 아래 수치는 테스트 결과예요.

  • 5 → 1

    메뉴 확인까지 거치는 화면 수

  • 38초 → 9초

    오늘 메뉴를 찾는 데 걸린 평균 시간

  • 5 / 5

    안내 없이 메뉴 확인에 성공한 참여자

배운 점

  • 사용자가 말한 불편보다, 실제로 앱을 닫는 순간을 관찰했을 때 진짜 문제가 보였어요.
  • 제 직관과 테스트 결과가 다를 때, 결과를 따르는 기준이 생겼어요.

다음에 바꿀 점

  • 참여자가 5명이라 학년이나 시간대별 차이는 확인하지 못했어요. 다음에는 표본을 늘리고 싶어요.
  • 식당 운영자 인터뷰를 하지 못해, 품절 정보를 실시간으로 받는 방법은 가정으로 남았어요.
